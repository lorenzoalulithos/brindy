# How to build a Brindy game

Brindy = 3D party/drinking games app (React 19 + Vite + TypeScript + three.js via @react-three/fiber 9, drei 10, @react-three/rapier 2, zustand). Web first, later wrapped with Capacitor for iOS/Android.

**Reference implementation: `src/games/dice/` — read it first and copy its structure.**

## Hard rules
1. A game lives entirely in `src/games/<id>/` with a default-exported component `({ onExit }: GameProps)` from `index.tsx`. Its metadata (name, rules, color, minPlayers) is already in `src/games/registry.ts` — don't edit the registry or any file outside your game folder. If you think shared code needs a change, describe it in your final report instead.
2. Wrap everything in `<GameShell gameId=... onExit=... scene={<Stage>…</Stage>} top=... bottom=... overlay=...>` (`src/ui/GameShell.tsx`). Use `TurnPill`, `ResultCard`, `Sheet` from there and the CSS classes in `src/index.css` (`btn`, `btn secondary|yellow|cyan`, `block`, `small`, `chip`, `result`, …).
3. **Penalties go through `usePenalty()`** (`src/core/penalty.ts`): `drink(n)`, `give(n)`, `all(n)`, `apply(playerId, n)`. Never hard-code "drink/bevi" text: the user may be in alcohol-free "points" mode or "dares" mode. This is what keeps us App Store / Play compliant.
4. **Few taps for drunk people.** Main action = one huge button at the bottom (or tapping the 3D object). No typing during play, no tiny targets, no multi-step menus. Setup (if any) must be ≤ 2 taps with sensible defaults.
5. **Every visible string in 5 languages**: it, en, es, fr, de. Use the `Loc` type and `useT()` → `L(loc)` for game content, `t(key)` for existing UI keys (see `src/core/i18n.ts`). Content (cards/prompts) also needs all 5 languages, written naturally (not literal translations; adapt idioms).
6. **Store-safe content**: party-fun and cheeky is fine ("sopra le righe"), but no explicit sexual content, no drugs, no encouraging dangerous amounts (no "down the bottle", no chugging contests), no hate/harassment, nothing involving minors. Spicy/adult-leaning (but non-explicit) cards must be flagged `spicy: true` and shown only when `useApp(s => s.spicy)` is on **and** the pack is unlocked via `usePack('<id>-spicy')` from `src/ui/PackLock.tsx` (show `<PackLockSheet>` when locked). Max penalty per event is 5 (drink(5) renders "SHOT!").
7. **3D look**: stylized, glossy, neon party vibe. Use `<Stage accent={color} camera=…>` (`src/three/Stage.tsx`) which gives lights, env map, contact shadows and a round bar table with top at y=0 (pass `table={false}` if you need another surface). Portrait phone (390×844) is the primary viewport — keep the action centered and in frame; bottom ~35% of the screen is covered by HUD. Animate with `useFrame` (springy easing, squash/stretch, particles) — things should feel juicy. Physics via rapier is available (see dice).
8. **No network assets**: no drei `<Text>` (downloads fonts), no `Environment preset`, no GLTF downloads. Draw text/faces on canvas with `canvasTexture`, `fitText`, `roundRect` from `src/three/textures.ts`. Build models from primitives (lathe, extrude, rounded boxes from drei are fine — `RoundedBox` works offline).
9. Feedback: `sfx.*` and `vibrate()` from `src/core/feedback.ts` on every meaningful moment. Turns: `useTurn()` from `src/core/useTurn.ts` (works with zero players via a guest). Randomness helpers in `src/core/random.ts` (`createDeck` for non-repeating cards).
10. Dispose nothing manually unless you create heavy resources in loops; memoize textures/materials with `useMemo`.
11. Code style: match the existing files (2-space, no semicolons, single quotes, comments only where non-obvious). Must pass `npx tsc -b` and `npx eslint src/games/<id>` with **zero errors**. Do NOT run the dev server or a browser (others are using them); the lead will do visual QA.
